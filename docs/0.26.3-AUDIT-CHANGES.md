# Revit MCP 0.26.3 audit and change record

26 November 2026 · Revit 2024 and 2027 · native bridge protocol 4 · Python MCP SDK 1.30.0

## Executive summary

The patched source builds for both Revit years and passes the simulated MCP suite. Release readiness remains conditional. The most consequential fixes concern who can discard an open model, which model a live test can edit, and when a transaction can be retried. The native export overwrite race remains open. The existing packaged executable also emitted a shutdown traceback. Neither patched DLL was loaded into Revit in this pass.

The working tree identified itself as 0.26.3 and the local Git HEAD was `de44491`. The tree already contained edits and untracked files. A diff against HEAD includes the user's intervening work. The file inventory below records changes made in this recheck. For the earlier patch and incoming feature history, see the [0.17.0 audit changes](0.17.0-AUDIT-CHANGES.md), [implementation history](IMPLEMENTATION_LOG.md) and [release notes](../CHANGELOG.md).

## Findings by severity

Severity reflects the possible consequence. A code path that can discard edits is a high-severity finding even when no loss was observed. No critical defect was confirmed in the reviewed paths.

### High

| Status | Category and location | Defect and consequence | Correction |
| --- | --- | --- | --- |
| Fixed in source | Document ownership · `plugin/Read/DocumentActions.cs`, `Open`, `OwnedSource`, `ModelClose` | Close permission survived a manual close and reopen of the same file. The old key described the model in the process, so a later user-opened instance could be closed with changes discarded. | Track the actual open Revit document and prune invalid objects. Check Revit's close result before releasing ownership. |
| Fixed in source | Wrong edit target · `tests/live_hvac.py` and `tests/live_hvac2.py`, setup, edit and cleanup | Resolving the active document again immediately before a real edit could select the user's newly active model. A reused model could also contain existing user work. | Require a newly opened active HVAC copy, verify its returned ID against the pinned connection, and reuse that ID for writes, permission probes and close. |
| Fixed in source | Test side effects · `tests/exe_check.py`, `main` | A validation probe supplied a real purge with a misspelled preview flag. A binary that ignored that flag could attempt the very operation the check was supposed to protect. | Use an empty batch and require the specific unknown-parameter error. This tests the typo without sending an executable edit. |
| Fixed in source | Transaction replay · `plugin/Edit/EditEngine.cs`, commit retry branch | A noncommitted transaction containing any join could replay unrelated operations. Deferred callbacks were cleared but reserved export targets survived in the reused edit context. A retry could falsely report a duplicate destination. | Require a confirmed rollback and a batch containing only `join_overlaps`. Keep the three-retry ceiling and require a newly identified conflicting element. Return the actual status for other failures. |
| Open | Export publication · `plugin/Edit/EditContext.cs`, `GuardOverwrite`, and deferred exporters in `plugin/Edit/ExportOps.cs` | The existence check precedes the export. A competing writer can create the destination between those steps. Multi-file output can also be left incomplete. The precise overwrite behavior depends on the exporter. | Stage the actual outputs and publish with filesystem-enforced no-replace semantics. Define partial-publication recovery and verify each exporter in Revit. |

### Medium

| Status | Category and location | Defect and consequence | Correction |
| --- | --- | --- | --- |
| Fixed in source | Dispatch and schema · `server/server.py`, `revit_edit` and `_run`, and `server/catalog.py` | Split mode directed worksharing to the edit tool but had no way to express the four standalone actions. Their result payloads also bypassed the shared failed-outcome check. | Add a mutually exclusive worksharing call shape and route it to the existing validator, permission and receipt path. Apply the same failed-outcome translation as for edit operations. |
| Fixed in source | Batch side effects · `DocumentActions.BatchRead` | The model open, new and close actions were registered as reads and passed the nested batch check. A zero or very small time budget could leave the caller without usable progress. Background close failures could disappear. | Exclude the three session-changing actions, reject nonpositive budgets, attempt the first pending file, and return cleanup failures in `closeErrors`. Stop opening further files on cleanup failure. The time limit is checked between files. |
| Fixed in source | Activation and worksharing state · `DocumentActions.Open` and `ModelOpen` | An existing background model could be returned for an activation request without activation. Reusing a user-opened workshared model also preserves its attachment state despite the earlier blanket detachment message. | Verify activation of an existing supported document. Give explicit feedback for background detached or pathless documents that require manual activation. Describe the reuse case in the response and catalogue. |
| Fixed in source | Phase-sensitive edits · `plugin/Edit/SpaceOps.cs`, `SpacesFromRooms` | The fallback compared existing space names, numbers and levels across phases. A different phase could suppress creation. The snapshot also omitted spaces created earlier in the same operation. | Limit fallback candidates to the target phase and add each newly created space to the candidates. |
| Open | Document targeting · `plugin/Core/DocumentTarget.cs`, `ModelKey`, `SessionId` and `Verify` | Reopening the same file in the same Revit process can reproduce the same public document ID. Fixing close ownership addresses discarded edits through `model_close`. A previously issued edit target can still match the reopened file. | Add a per-open-instance identity for live targeting. Preserve a separate stable model identity for persisted workbook references and test the migration. |
| Open | Access semantics · `server/server.py`, split `revit_read`, and `DocumentActions.ModelClose` | The split read tool can close a bridge-owned inactive model with `Close(false)`. It returns whether changes were discarded only after closing. Its destructive tool annotation is accurate, but granting read-tool access grants this capability too. | Put a discard of modified work behind an explicit edit-capable route and explicit discard intent. Define compatibility for current callers and cover both tool modes. |
| Open | Room selection · `SpaceOps.SpacesFromRooms` | `rooms.Take(max)` runs before the host-level filter. Requested levels can get zero spaces even when matching rooms occur later. Repeating the same request starts at the same prefix. | Apply the limit after level matching, define stable room ordering, and report truncation with a continuation identifier. |
| Open | UI queue and cancellation · `plugin/Bridge/MainThread.cs`, `Run`, `Execute` and `Shutdown` | Timed-out queued items become inert but stay queued until a callback drains them. Shutdown does not drain or fail queued waiters. An already running native call waits for completion. | Bound pending work, complete queued waiters on shutdown, and limit work per UI callback. Preserve receipts for work that already started. |
| Open | Input resource use · `server/excel_io.py`, workbook readers | Import can materialize workbook data before edit batch limits apply. Batch limits do not bound expanded workbook size or total cells parsed. | Check archive and expanded sizes before opening. Apply sheet, row and cell budgets while streaming, before dispatching any edit. |
| Open | Release packaging · `build_package.bat`, staging and `:release` | The script removes the previous distribution before verifying its replacement, accepts an offline prebuilt DLL without a source manifest, and checks the staged executable's existence without running its handshake. | Stage beside the last good distribution, verify artifact identities and run stdio probes on the staged executable before promotion. |
| Open | Audit evidence · `plugin/Core/Audit.cs`, `Write` | Separate Revit processes can race while rotating or appending a shared log, and write failures are suppressed. A missing entry cannot establish the outcome of an edit. | Log per process or synchronize rotation and append across processes. Report audit health separately from model transaction success. |

The server uses SDK-managed stdio. The tested initialization order and unknown-tool response match the official lifecycle and tool error model. A successful client handshake does not by itself establish how the SDK handles every out-of-order message, cancellation, malformed frame or version. The TCP channel between the Python adapter and Revit is the application's private protocol. No SSE or HTTP endpoint was exercised. ## Behavior-preserving cleanup opportunities

- Share the target-check, result-check and teardown helpers used by the two HVAC harnesses. Parameterize their machine-specific fixture paths while retaining the new-document guard.
- Give registry entries an explicit batch eligibility property. The current exclusion list must be kept in sync whenever another document-session action is registered.
- Keep machine-readable per-operation schemas adjacent to handlers and derive their catalogue descriptions. Preserve accepted aliases and older workbook inputs, and test against both Revit versions before tightening individual schemas.
